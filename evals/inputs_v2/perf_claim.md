# 一个性能优化结论（待核实）

## 我们做的实验

接口 `GET /feed` 之前 p99 是 800ms。我们做了一件事：把序列化库从 Jackson 换成 fastjson2。换完之后观测了一天，p99 降到了 450ms。

## 我下的结论

**Jackson 的序列化性能太差，是这个接口的主要瓶颈；换成 fastjson2 直接让接口快了接近一倍。后续所有服务都应该统一从 Jackson 迁移到 fastjson2。**

## 补充信息（实验当时的一些情况）

- 换库这次发布，同时还把这个接口的数据库查询加了一个索引（顺手做的，没太在意）。
- 观测"前后对比"用的是发布前一天 vs 发布后一天的 p99，不是同一时段灰度对比。
- `/feed` 返回的 JSON 不算大，单条响应大概 5~20KB。
- 没有单独对序列化这一步做过 micro-benchmark。
